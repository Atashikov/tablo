# Учебная платформа — https://atashikov.github.io/tablo/

Статический сайт на GitHub Pages; общие данные (расписание Zoom, курсы, категории, анкета) хранятся в Supabase. Входа и ролей нет: любой посетитель может добавлять и менять записи. Правки видны всем сотрудникам без перезагрузки (Realtime + резервный опрос раз в 15 секунд и при возврате на вкладку).

## 1. Применить SQL (один раз, владелец проекта)
1. Supabase → проект `zvzeyplkanvaazjhxcbv` → **SQL Editor** → New query.
2. Вставьте `sql/01_setup.sql` → **Run**. Затем `sql/02_seed.sql` → **Run** (3 категории, 60 курсов, анкета).
3. Затем `sql/03_atomic_apply.sql` → **Run** (серверная функция `tablo_apply_changes`: атомарный импорт и сохранение списка Zoom ID). Без неё эти два действия покажут ошибку, остальное работает.
4. Выполните `select * from public.tablo_booking_overlaps;` — должно быть пусто. Если есть строки, ограничение `bookings_no_overlap` не создано (в Run будет предупреждение): разберите пересечения вручную и запустите `01_setup.sql` ещё раз.
5. Повторный запуск всех трёх файлов безопасен: данные не удаляются и не дублируются.

## 2. Загрузить в GitHub
Замените в корне репозитория `tablo`: `index.html`, `supabase-config.js`, `assets/app.js`, `assets/app.css`, `catalog.json` (теперь только исходный набор/копия), `README.md`; добавьте `sql/` (три файла) и `source/`. Файл `.nojekyll` оставьте.

## 3. Проверка на двух устройствах
Откройте сайт на двух устройствах. На первом создайте/измените/удалите бронирование, добавьте курс и смените ссылку, измените анкету — на втором всё должно появиться за секунды без перезагрузки. В «Управлении» видно связь, режим обновления и время последнего чтения.

## Где настройки
`supabase-config.js`: адрес проекта и publishable key (для браузера). Не вставляйте туда service_role, secret key, пароль базы или токен GitHub.

## Сборка
`cd source && npm ci && npm run build` (результат — `assets/app.js`). Версии зависимостей закреплены в `package-lock.json`; node_modules в архив не входят.

## Конфликты правок и атомарность
- У каждой записи версия — `updated_at`. Форма запоминает версию **в момент открытия** (снимок), и фоновые обновления её не подменяют. Изменение и удаление проходят только если на сервере версия равна снимку; иначе показывается сообщение, данные обновляются, форму нужно открыть заново.
- **Zoom ID:** отправляются только строки, которые вы изменили или удалили в диалоге, каждая с версией из снимка; строки без ваших правок и новые Zoom ID других сотрудников не затрагиваются. Всё сохраняется одной транзакцией: при конфликте не применяется ничего.
- **Импорт файла** (Управление и «Расписание Zoom» → «Загрузить из файла»): перед подтверждением сайт читает свежий снимок сервера; функция `tablo_apply_changes` применяет все записи из файла одной транзакцией. Если любая затрагиваемая запись после снимка была изменена, создана или удалена другим сотрудником — импорт отклоняется целиком, данные остаются как есть. Записи, которых нет в файле, не удаляются.
- Двойное бронирование Zoom блокирует сервер (`bookings_no_overlap`, обе границы дат включены).
- Если другой сотрудник создал запись с тем же ID между проверкой и записью, импорт отклоняется целиком. Созданная запись не перезаписывается.
- При потере связи во время сохранения ответ сервера может не дойти, хотя операция завершилась. Сайт сообщает, что подтверждение не получено. Обновите данные перед повторным сохранением или импортом.

## Резервные копии
«Управление» → «Скачать резервную копию»: перед скачиванием данные читаются с сервера. Если сервер недоступен, показывается ошибка и файл не создаётся; данные из памяти страницы за серверную копию не выдаются. Формат — `catalog.json`. Старая копия расписания загружается внизу раздела «Расписание Zoom» и затрагивает только расписание. Старый локальный черновик браузера (если найден) можно скачать или удалить; в общие данные он не подставляется.

## Лицензии
QR-генератор — qrcode-generator К. Араси (MIT), из пакета qrcode-terminal.

## Проверки перед передачей
На локальной тестовой базе PostgreSQL и в двух изолированных сессиях проверены: общее сохранение курса, конфликт старой формы анкеты, сохранность нового Zoom ID другого сотрудника, полная отмена импорта при ошибке SQL или изменении версии, успешный импорт и запрет скачивания копии без связи. Отдельно проверена защита записи, появившейся между проверкой и сохранением, и сообщение при потере ответа после выполненного импорта.

В рабочем Supabase SQL и файлы GitHub необходимо применить отдельно; после этого выполните проверку на двух устройствах из раздела 3.
